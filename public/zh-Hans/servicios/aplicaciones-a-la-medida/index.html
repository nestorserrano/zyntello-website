解决什么问题

没有哪个标准产品，刚好覆盖你那个特殊情况

每家公司都有一个套不进去的流程：要么是让它领先的那个，要么是从来都这么干的那个。硬塞进标准产品里只会更糟，而为了这一块换掉整套系统又不成比例。真正需要的，是为它专门做的一块。

  • 让你与众不同的那个流程，哪个产品都装不下
  • 买下整套系统，却只用得上 20 %
  • 数据都在，却没人能按需要的方式查出来
  • 外勤人员没法在现场把记录录进去
  • 每个客户都要自己那份报表，全靠人手工拼出来
  • 为了一项功能就换掉整套 ERP，不成比例

包含什么

具体给到你什么

建在你已有的东西之上

应用直接读写你现有的数据库。不用迁移，也不会多出一个让数据重复的地方。

网页端与手机端

可以装在手机上的应用，给在外面跑的人用：路线、打卡、盘点、送货。工作在哪里，它就在哪里能用。

给你客户用的自助门户

让他们自己查对账单、订单或案卷，不用打电话。每一次自助查到，就少一通来电。

用来做决策的看板

只放真正会被看的那些数字，自动刷新。历史数据够的时候，也包括预测分析。

系统集成与 API

让你的各个系统彼此对话，也能和客户、供应商的系统对话，而不是靠谁手动发一个文件。

源码和数据都交给你

连同文档一起。我们做出来的东西是你的，这也包括你可以把它带去找别的供应商。

如何运作

三步完成

  1. 先把流程搞清楚

    今天是怎么做的、谁在做、哪里出问题。

  2. 先做一个短小的第一版

    只做已经能用的最小部分，先用起来再调。

  3. 随着使用再往上加

    加真正被要求的东西，不是一开始设想的那些。

细节之处

每天用起来才感受得到的地方

从能解决问题的最小那一版开始

一个短小但已经能用的第一版，胜过六个月的需求文档。哪些是多余的，用起来才看得出来。

往别的系统的数据库里写，是有规矩的

必须遵守它自己的校验规则，否则 ERP 里会出现连它自己都认为不可能存在的数据。所以要先分析清楚。

外勤 App 必须在没信号时也能用

如果非要一直联网，技术员就会先记在纸上、回头再录入——而这正是当初要避免的事。

客户门户是对外开放的

外面的人会看到它，所以"谁能看到什么"这件事要先设计，而不是最后再补上去。

没有文档，就不算完全是你的

交给你、却没人看得懂的源码，照样把你绑住。所以它连同文档和写清楚的数据结构一起交付。

有时候，答案是不要做

如果平台里的某个模块、或者 ERP 的一项设置就能解决，我们会直说。这样双方都更省钱。

常见疑问

常见问题

我必须换掉现在的系统吗？

不用。我们直接建在你已经在用的数据库上，并遵守它自己的规则。

你们做手机 App 吗？

做。可以装在手机上，而且就是按"没信号也能用"来设计的：一旦非要联网，技术员就又回去用纸了。

源码归我吗？

归你，连同文档和数据结构一起。交给你、却没人看得懂的源码，照样把你绑住。

要做多久？

第一版做得短、交得快，是有意为之：先用起来，再调整，再按真正被要求的东西扩展。

如果我要的东西已经有了呢？

我们会直说。如果平台的某个模块、或者你 ERP 的一项设置就能解决，这样双方都更省钱。

你们用哪些技术？

React、Node、PHP/Laravel、Python、SQL Server 和 MySQL 等等。具体选哪一种，由必须与之共存的那套系统决定。
